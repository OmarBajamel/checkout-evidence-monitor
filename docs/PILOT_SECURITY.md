# Bounded pilot security design
Implementation supplement to V1.1-dual-purpose.1. Runtime validation pending.

The host owns immutable evidence, private target/grant configuration and the SQLite queue. The local UI authenticates to the same-origin loopback API. Configuration is declarative data, never evaluated code. Target authority is an operator attestation, not legal proof; local files are not a tamper-proof identity mechanism.

The browser runs nonroot in a read-only container with Chromium sandbox enabled, no Linux capabilities, no-new-privileges, pinned seccomp, memory/PID/CPU/output/time limits. It joins an IPv4 internal Docker bridge in isolated gateway mode. A separate bounded CONNECT proxy joins that bridge and an external bridge. Neither publishes a port. An ordinary internal bridge still has a host gateway address, so the wrapper requires and inspects isolated gateway mode; unsupported engines fail closed. See [Docker gateway modes](https://docs.docker.com/engine/network/port-publishing/#gateway-modes).

The browser gets a literal proxy IP and DNS 127.0.0.1, avoiding Docker's embedded external DNS forwarder; see [Docker network DNS](https://docs.docker.com/engine/network/). No host network, host PID/IPC, device, Docker socket or broad host mount is allowed. Both containers have only narrow read-only input binds. Browser output uses a 50 MiB noexec tmpfs, inspected before start; no writable host output mount exists. The wrapper copies one size-checked regular JSON file, rejects symlinks, validates the complete profile and deletes its transfer copy. Container logs are disabled. Browser cleanup precedes a bounded 60-second handoff hold; host cleanup normally ends it sooner. The host, local Docker daemon and kernel remain trusted. This is not a containment proof against exploits or a hostile administrator.

The proxy accepts only exact allowlisted hostname:443 CONNECT authorities. Every connection re-resolves and rejects the whole DNS answer set if any address is non-public, mapped IPv4, transition/translation, multicast or reserved. It dials the validated literal address without a second hostname lookup. TLS stays end to end and the browser validates certificates. It bounds concurrent connections, request count, aggregate bytes and grant deadline. No raw URLs, bodies, proxy transcripts or cookie values are written to disk.

Playwright additionally restricts methods to GET/HEAD, denies WebSockets/service workers/popups/downloads and limits top-level/frame navigation to exact approved paths. Read-only HTTP methods do not guarantee a remote server has no side effects; scope must exclude action URLs. HTTP paths/methods are an application enforcement layer inside the TLS tunnel, not independently inspected by the egress proxy. A compromised browser can contact approved public endpoints until the short grant expires. A malicious authorized origin could itself relay requests; allowlisting does not attest its ownership or safety.

The browser may execute remote page JavaScript inside its sandbox. Retained evidence is inert metadata and response hashes. Main-frame correlation is bounded; third-party frame coverage remains partial. Navigation states are operator labels verified by a required visible selector, not proof of checkout state. No authenticated sessions, inputs, order creation, payment, CAPTCHA bypass or exploitation.

Only wrapper-collected pilot records receive COLLECTED_PILOT provenance. Imported records cannot assert it. Pilot artifacts retain approved origins but mask all paths/query values and pseudonymize cookie names. Private configuration remains local and is excluded from publication and evidence exports. Existing LAB import sanitization is unchanged.

A runtime approval session for PILOT is distinct from OFFLINE_AND_LAB. Runtime approval alone grants no merchant authority. The grant is rechecked before queue admission, launch, every browser request, and proxy tunnel setup; the hard run deadline is capped by grant expiry. Revocation/pause cancels queued jobs and requests termination of active containers. Failed cleanup is surfaced and blocks subsequent work until resolved. Restart recovery never calls a lost in-flight observation successful.
