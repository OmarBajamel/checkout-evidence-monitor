LOCAL / V1.1

From first visit to a review decision.

This local pilot increment is awaiting runtime verification. Keep the original workbench tab open while reading this guide.

  1. Prepare your local environment

    The source package uses Python 3.12, Node 24 and a project-local installation. Follow README.public.md and docs/PILOT_QUICKSTART.md in your project folder for the exact locked build commands. A supported local Linux Docker engine is required for collection.

  2. Configure a paused target

    In Assessments, open Monitoring → Set up store. Enter your HTTPS origin, authorizing operator and exact public paths. Every visited state needs a visible CSS selector. Declare any approved resource origins, choose a cadence and review the short-lived grant.

    No sign-in, form filling, order, payment or account action is supported. Saving starts no collection.

  3. Start only the authorized runner

    A regular workbench can review evidence and save setup. Collection additionally needs explicit pilot runtime approval, the reviewed network/sandbox boundary and authority for the specific store. The quickstart explains source-bound image preparation and cem ui --monitor. Earlier synthetic LAB approval does not cover a store.

  4. Establish a comparison reference

    Choose Run once. Review the observed Journey and its limitations. Select the visit in Recorded visits, choose Select saved baseline, write a reason, review and confirm.

  5. Follow a difference to its evidence

    Start cadence for the authorized period. The runner must remain active. Inbox notices distinguish differences from failed or partial observations. Open a pair, inspect both sides, record your decision and export the review bundle.

  6. Keep the limits visible

    Pause requests cancellation. A missed cadence is an unobserved gap. An expired grant requires a new authorization. A new script is not automatically malicious; missing evidence does not establish safety or disappearance. Notifications remain in the local inbox.

The project is complete as an operational product only after a supported operator can finish this cycle and the research can be reproduced. Build success alone does not demonstrate either outcome.
